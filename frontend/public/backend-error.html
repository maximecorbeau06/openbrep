Échec du démarrageLe service interne de MM STUDIO GDL n’a pas démarré

La fenêtre de l’application s’est ouverte, mais le processus Python intégré n’est pas prêt. Causes fréquentes : vérification de sécurité de macOS trop longue au premier lancement, plantage du processus, ou port occupé par un autre programme.

À essayer d’abord

  1. Quittez complètement l’application (⌘Q), patientez quelques secondes puis rouvrez-la. Le premier lancement est lent : comptez jusqu’à deux minutes.
  2. Vérifiez qu’aucun autre programme n’occupe le port 8765 (par exemple une ancienne version d’OpenBrep ou obr serve encore en cours).
  3. Si vous venez de copier l’app depuis le DMG, vérifiez qu’elle se trouve bien dans le dossier « Applications » et qu’elle n’est pas lancée directement depuis le DMG.

Voir l’erreur détaillée

Le détail est écrit dans ce fichier journal :

~/Library/Logs/fr.mmstudio.gdl/startup-error.log

Dans le Finder, faites ⇧⌘G et collez ce chemin. Vous pouvez aussi lancer la commande suivante dans le Terminal pour voir directement la sortie du service :

"/Applications/MM STUDIO GDL.app/Contents/MacOS/openbrep"

Toujours bloqué ?

Envoyez le contenu de startup-error.log (avec votre version de macOS et le type de processeur) à GitHub Issues.
